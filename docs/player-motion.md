# Cadence animation quality correction

Scope: motion on existing controls and surfaces. The correction does not add a control, artwork slot, card, section, or background mode. It does not change `state/playerStore.ts`, the audio engine, the authoritative queue, lyric parsing/timestamps, or the Tauri bridge/commands.

The pre-edit trace (`.artifacts/motion-quality/before/`) observed seven navigation callback gaps over 25 ms (max 100 ms) and three in Mini expansion (about 33 ms each), across three samples per action. Queue insert/remove and lyric follow did not miss that threshold in those samples. Concurrent route trees, per-descendant handoff style reads, extra backdrop layers, and color sampling were concrete costs in the code; the trace did not isolate each one's share of the gaps.

## What the correction does

Restored the text-only windowed header and existing Customize placement, the original Studio guidance, the Mini radial background, the player-bar artwork blur and setting label, and the original Now Playing backgrounds. Reverted the previous track-identity change in `useLyrics.ts` and the forced windowed mode on the Mini artwork action. Removed the extra nav press/link treatment and eliminated the concurrent outgoing browse tree, cloned player layers, sampled washes, and long-seek whole-view dip.

| Trigger | Start → end and what is visible | Timing / implementation |
| --- | --- | --- |
| Close/open Mini from the existing button or shortcut; click Mini cover or Restore | The existing cover, title, and transport start from the outgoing surface's displayed positions and move into the actual Mini or full player slots. Windowed Now Playing uses the existing **player bar**, not a fake hero. Restore keeps the route; the cover goes to Now Playing. The real play button is clickable in flight; seek stays on its normal clock. | **300 ms**, transform only (`features/player/PlayerLayoutMotion.tsx`, `useMiniWindow.ts`, `MiniPlayer.tsx`, `PlayerBar.tsx`, `PlaybackControls.tsx`, `styles/playback-motion.css`). Snapshot geometry is read before and after the commit, including title/play anchors, not on every frame. No artwork/text clones. Fullscreen uses its existing visible slots; a 48 ms artwork/heading stagger fits inside the 300 ms envelope. Hidden slots do not fly. Resizing cancels stale geometry; reversing samples the in-flight geometry. The bridge restore precedes expansion and shrink follows collapse. Bar backdrop sampling pauses during the flight; its artwork blur remains. |
| Skip, advance, or choose another track | Old cover stays visible while the next URL decodes. Once ready, the incoming pixels fade over it at the same size; failure settles to the existing fallback. Metadata commits on the track change itself; the outgoing title recedes and the incoming title rises 5 px into the same slot. | **320 ms** cover opacity-only, **240 ms** text envelope (120 ms exit; 180 ms entry after a 60 ms delay). `features/player/{usePlaybackPresentation.ts,PlaybackVisuals.tsx}`, `app/useDissolve.ts`, `styles/playback-motion.css`, `features/lyrics/LyricsView.tsx`. One current and at most one outgoing layer per visual. Duplicate in-flight decodes share a request; up to 32 successful URLs are remembered, not pixel buffers. A layout remount can take the held cover without redecoding it. No sampled accent or animated blur radius. |
| Playback crosses a synced line; user seeks | The active line follows the actual audio clock, and the neighboring lines travel to the new scroll target instead of jumping. A long seek lands on the correct group without a decorative host-wide dip. | **240 ms** built-in compensated movement; authored Custom theme timings remain. `features/lyrics/BraccatoLyrics.tsx`, `upstream/better-lyrics/themes.ts`, `styles/lyrics.css`. Keeps the existing lyric scale, karaoke clock and source-upgrade behavior. Inactive/hidden lyric rendering does not run a local media frame loop. Reduced motion skips line travel but preserves timed highlighting. |
| Click a different main sidebar destination | The same active indicator travels from its last location to the selected nav slot. The new route is the only live route; existing route entrance and saved scroll still work. | **240 ms** transform between cached slot positions. `app/Sidebar.tsx`, `App.tsx`, `styles/global.css`, `app/motion.ts`. Slot heights are set, not animated. Width-only hover updates don't remeasure vertical slots or restart the slide. |
| Insert with Play Next, remove, or reorder visible queue occurrences | New row fades/rises 8 px. A removed row leaves the active queue immediately and drifts 10 px right while fading; neighbors translate from their old top to their real new top. Intentionally no long travel from offscreen. | **180 ms** insert, **120 ms** exit, **240 ms** neighbor travel (`features/player/{QueueMotionList,QueuePanel}.tsx`, `app/layoutMotion.ts`, `styles/global.css`). Up to 16 visible/edge rows sampled and two inert detached rows reused in a clipped exit list. Geometry reads are batched before starting animations. The drawer itself keeps its original entrance/exit. Scroll, resize, preference changes, closing, and another edit clean up or interrupt motion. |

There is no new animation dependency, blanket `will-change`, or JS per-frame interpolation of the handoff, sidebar or queue. Player control subscriptions remain scoped, and current-row changes do not rebuild unchanged queue rows.

## Performance: prior pass vs. corrected renderer

Both versions ran as production builds in HeadlessChrome 153 with SwiftShader on a two-vCPU sandbox, 1440×900 and a simulated 460×160 native Mini resize. The harness uses 24 local fixture tracks, actual cover pixels and audio, and the existing Lyrics Focus blurred-artwork profile; optional shaders, artist-image lookups, autoplay and audio crossfade are off to keep the workload comparable. Each scenario has six unpaused 520 ms samples (three in each of two browser launches per version). Navigation is Home → Songs. The lyric sample crosses a line at the real media clock. CDP counters cover each action sample; lyric task time also includes its short preroll. Still capture runs after tracing stops.

| Interaction | rAF p95, ms | Worst callback gap, ms | Intervals >25 ms | Median layout / style counts | Median main-thread task time, ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| Idle | 16.7 → 16.8 | 16.8 → 16.8 | 0 → 0 | 0 / 0 → 0 / 0 | 12.3 → 11.7 |
| Navigation | 33.3 → 33.3 | 100.0 → 83.3 | 14 → 9 | 17 / 21 → 18 / 19 | 106.8 → 91.8 |
| Cover + metadata | 16.7 → 16.8 | 33.4 → 66.6 | 2 → 3 | 12.5 / 29 → 12 / 27.5 | 108.8 → 111.3 |
| Active lyric follow | 16.8 → 16.8 | 16.8 → 33.4 | 0 → 2 | 14 / 54.5 → 14 / 54 | 151.3 → 142.1 |
| Mini → Now Playing | 16.8 → 16.8 | 50.1 → 66.7 | 8 → 4 | 13 / 43 → 14 / 41.5 | 159.9 → 111.7 |
| Queue drawer open | 16.8 → 16.7 | 33.3 → 16.8 | 1 → 0 | 3 / 19 → 3 / 19 | 61.3 → 55.8 |

Navigation mounted less at once, with fewer long gaps; its p95 still exceeds the 16.67 ms target. Mini expansion did about 30% less main-thread task work and produced half as many long gaps, but one gap was longer than the previous worst. Queue edits stayed near the target. Cover swaps and lyric follow had occasional longer gaps in the corrected sample, so they are not a measured improvement in pacing. An intermediate trace also exposed the queue reading `offsetTop` after every animation start (15 layouts in a removal sample). Batching reads and keeping the inert exit outside the scrollport brought the final removal median to three layouts. Cold route mount work, style/paint/compositing and occasional GC showed up in traces; the measurements don't establish a single cause for each gap.

These are **callback interval and workload measurements**, not presented-frame FPS or power/GPU measurements. Native Tauri resize order is simulated; OS window-manager behavior and the Intel UHD 60 FPS target still require a run on the actual desktop. This sandbox lacks the native Tauri toolchain and physical GPU.

Raw samples (`profile.json`) and compressed Chrome traces (`trace.json.gz`) are in `before/` and `previous/` for `b01e052`, and `after/` and `after-repeat/` for the correction.

## Verification and reproduction

The production web build and typecheck passed, as did animation (102/102), Now Playing (120/120), lyrics UI (40/40), audio (11/11), and offline unit tests (610/610). The animation audit measured the third lyric moving about 57 px over 15 distinct positions, verified live transport hit-testing in flight, retained art through a delayed decode and layout switch, checked hidden fullscreen art and rapid reversal, and observed the mock native resize sequence `[true, false]`. The older `test:ui` harness was not used as a pass signal: it also fails on the original base when its mock settings omit `artistImages` on Songs. No production fallback or test workaround was added for that unrelated harness issue.

Generate the audio fixtures with `python3 tests/fixtures/generate-audio.py`. Run `npm run typecheck`, `npm run build`, `npm run test:animation`, `npm run test:now-playing`, `npm run test:lyrics-ui`, and `npm run test:audio`. Run the offline unit suite with `npm test -- --exclude tests/unit/_matasaburo_full.test.ts` (that separate suite needs a local provider key).

`CADENCE_MOTION_RUN=after npx vite-node tests/browser/animation-audit.ts` runs the performance workload instead of the functional audit, serving the production `dist`. To use identical stimuli on a previous build, point `CADENCE_PROFILE_DIST` to that build and use a different `CADENCE_MOTION_RUN` label. It saves `profile.json`, a Chrome trace, and actual start/mid/end screenshots under `.artifacts/motion-quality/<label>/`. The normal audit saves Mini both ways, artwork, lyric, navigation and queue frames under `.artifacts/animation-audit/`; `test:now-playing` separately exercises layouts and the original shader/canvas modes.
